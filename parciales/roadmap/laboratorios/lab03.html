Laboratorio 3

Traversal sequences stripped non-recursively

Información del laboratorio

Nombre del laboratorio:
Traversal sequences stripped non-recursively
Nivel de dificultad:
Practitioner
Tipo de explotación:
File path traversal
Objetivo del laboratorio:
Recuperar y desplegar el contenido del archivo de configuración del sistema /etc/passwd.
Explicación técnica de la vulnerabilidad:
La aplicación web intenta sanear la entrada del usuario eliminando las secuencias de salto de directorio ../ antes de procesar la solicitud del archivo. Sin embargo, el mecanismo de sanitización se realiza en una sola pasada (de forma no recursiva). Al anidar las secuencias en una estructura como ....//, la eliminación simple del patrón interno ../ vuelve a unir los caracteres restantes (.. + /), reconstruyendo la secuencia ../ en el string final que recibe la API del sistema de archivos.

Marco teórico

Un error

Su impacto en la triada CIA es significativo:

  • Confidencialidad: La exposición de archivos sensibles puede comprometer la confidencialidad de la información, permitiendo que datos privados sean accesibles para usuarios no autorizados.
  • Integridad: Si el endpoint vulnerable permite la escritura o modificación de archivos, un atacante podría alterar archivos críticos del sistema, comprometiendo la integridad de la aplicación y sus datos.
  • Disponibilidad: La manipulación de archivos esenciales para el funcionamiento de la aplicación puede afectar su disponibilidad, causando interrupciones en el servicio o incluso la caída completa del sistema.

Se clasifica bajo la categoría A01:2021 – Broken Access Control (Control de Acceso Deficiente).

Explicación del Payload

El filtro replace "../" no encuentra la secuencia y deja la entrada sin cambios. Al procesar la ruta, la función de unión detecta que el segundo argumento /etc/passwd es una ruta absoluta, por lo que ignora el prefijo previo /var/www/images/. De este modo, el sistema operativo resuelve la ruta directamente hacia /etc/passwd, accediendo a la raíz del sistema para leer el archivo de usuarios.

Recomendaciones de mitigación

Para prevenir vulnerabilidades de Absolute Path Bypass, se recomienda implementar las siguientes medidas de seguridad:Para prevenir vulnerabilidades de Path Traversal por bypass de ruta absoluta, se deben adoptar los siguientes patrones de desarrollo seguro:

  • En lugar de permitir que alguien pida directamente un archivo escribiendo su nombre o ruta (como imagen1.jpg o /etc/passwd), el sistema debe usar códigos o números de identificación
  • Si es estrictamente necesario que el usuario envíe un nombre, el servidor debe limpiar la entrada y quedarse solo con el nombre final, ignorando cualquier carpeta o diagonal previa
  • Antes de abrir cualquier archivo, el servidor debe calcular la ubicación exacta donde terminará buscando y confirmar que siga estando dentro de la carpeta permitida.
