Roadmap — Laboratorio 01

File path traversal, simple case

Nivel: Apprentice | Tipo: File Path Traversal

Marco Teórico

La vulnerabilidad de File Path Traversal (o directory traversal) ocurre cuando una aplicación web utiliza entradas del usuario de forma no segura para construir rutas del sistema de archivos sin realizar una validación o sanitización estricta[cite: 15].

Un atacante inserta secuencias de escape como ../ en sistemas Linux o ..\ en Windows para retroceder desde el directorio raíz configurado en el servidor web e ingresar a directorios restringidos del sistema operativo[cite: 15].

Impacto en la Tríada CIA

Confidencialidad: El impacto es alto, ya que permite la lectura no autorizada de código fuente, archivos de configuración con credenciales y datos sensibles del sistema[cite: 15].

Integridad / Disponibilidad: El impacto es bajo si solo se ejecutan ataques de lectura, pero el riesgo escala significativamente si se combinan con vulnerabilidades de escritura arbitraria o si se comprometen claves maestras[cite: 15].

Categoría OWASP y Defensa

Corresponde a la categoría A01:2025 - Broken Access Control de la OWASP Foundation[cite: 15].

Para la defensa se debe aplicar el principio de mínimo privilegio y reemplazar el manejo directo de rutas locales mediante listas blancas o identificadores indirectos e inmutables[cite: 15].

Detalles del Laboratorio

Nombre del laboratorio
File path traversal, simple case
Nivel
Apprentice
Tipo de explotación
File Path Traversal

Objetivo: Recuperar y visualizar el contenido del archivo /etc/passwd del servidor[cite: 15].

Vulnerabilidad: La aplicación procesa la solicitud de imágenes mediante un parámetro URL (filename). El backend lee directamente este valor e intenta resolver el recurso en el disco duro sin restringir que la secuencia de búsqueda salga de la carpeta /var/www/images[cite: 15].

Procedimiento

Payload utilizado: ../../../etc/passwd[cite: 15]

Suponiendo que la aplicación almacena las imágenes en la ruta /var/www/app/resources/images/[cite: 15]:

  • El primer ../ retrocede a /var/www/app/resources/[cite: 15].
  • El segundo ../ retrocede a /var/www/app/[cite: 15].
  • El tercer ../ retrocede a la raíz del sistema de archivos[cite: 15].

La adición de etc/passwd le indica al servidor que abra dicho archivo del directorio /etc/. Al no existir una validación que elimine los caracteres .. o /, el servidor ejecuta la lectura de forma nativa[cite: 15].

Mitigación Recomendada

Para solucionar esta vulnerabilidad se deben implementar prácticas de programación seguras[cite: 15]:

  • Evitar la entrada directa: No pasar nombres de archivos ni rutas provenientes de entradas del usuario a las APIs del sistema de archivos[cite: 15]. Utilizar identificadores numéricos o claves hash asociadas a una base de datos[cite: 15].
  • Validación de entradas: Validar rigurosamente los parámetros antes de procesarlos[cite: 15].
  • Verificación de ruta estricta: Verificar que la ruta absoluta resultante se mantenga dentro del directorio base permitido antes de realizar la lectura de archivos[cite: 15].
