Laboratorio 2

Traversal sequences blocked with absolute path bypass

Información del laboratorio

Nombre del laboratorio:
Traversal sequences blocked with absolute path bypass
Nivel de dificultad:
Practitioner
Tipo de explotación:
File path traversal
Objetivo del laboratorio:
Recuperar y desplegar el contenido del archivo de configuración del sistema /etc/passwd.
Explicación técnica de la vulnerabilidad:
La aplicación web maneja la carga dinámica de recursos multimedia mediante una solicitud HTTP GET que incluye el parámetro filename. El servidor backend consulta directamente el sistema de archivos local pasando el valor suministrado por el usuario sin sanitizar las secuencias de navegación ../. Esto permite romper la restricción de directorio (jail/sandbox) y leer archivos del sistema operativo subyacente.

Marco teórico

En muchas aplicaciones web, los desarrolladores intentan solucionar las vulnerabilidades de File Path Traversal aplicando filtros superficiales o listas negras que buscan y eliminan las secuencias de escape relativas ../ o ..\

Cuando el backend recibe la entrada del usuario y utiliza funciones nativas del sistema operativo, estas APIs interpretan tanto rutas relativas como rutas absolutas. Si la aplicación solo válida la ausencia de ../, pero acepta rutas que comienzan con el carácter de directorio raíz / (en sistemas UNIX/Linux) o una letra de unidad como C:\ (en Windows), la protección es ineficaz y permite un Absolute Path Bypass. Esto significa que un atacante puede especificar una ruta absoluta a un archivo sensible, eludiendo los filtros de seguridad y accediendo a recursos que deberían estar protegidos.

Por ejemplo, si la aplicación filtra ../ pero permite rutas absolutas, un atacante podría enviar una solicitud con un parámetro como /etc/passwd en un sistema Linux o C:\Windows\system32\config\SAM en un sistema Windows. Esto le permitiría leer archivos críticos del sistema operativo, exponiendo información sensible y comprometiendo la seguridad de la aplicación.

A diferencia de un ataque de Path Traversal tradicional, donde el atacante navega hacia arriba en la jerarquía de directorios, el Absolute Path Bypass permite especificar directamente la ubicación completa del archivo objetivo. Esto hace que la vulnerabilidad sea más peligrosa, ya que no depende de la estructura de directorios de la aplicación y puede ser explotada incluso si se han implementado medidas básicas de seguridad.

Su impacto en la triada CIA es significativo:

  • Confidencialidad: La exposición de archivos sensibles puede comprometer la confidencialidad de la información, permitiendo que datos privados sean accesibles para usuarios no autorizados.
  • Integridad: Si el endpoint vulnerable permite la escritura o modificación de archivos, un atacante podría alterar archivos críticos del sistema, comprometiendo la integridad de la aplicación y sus datos.
  • Disponibilidad: La manipulación de archivos esenciales para el funcionamiento de la aplicación puede afectar su disponibilidad, causando interrupciones en el servicio o incluso la caída completa del sistema.

En cuanto a OWAP Top 10, esta vulnerabilidad se clasifica como A5:2021 - Security Misconfiguration, ya que la aplicación no maneja adecuadamente la validación de entradas y permite el acceso a recursos sensibles debido a una configuración insegura.

Evidencias

A continuación se presentan las capturas realizadas en el procedimiento técnico del laboratorio:

Explicación del Payload

El payload utilizado en este laboratorio es "/etc/passwd". Este payload es una ruta absoluta que apunta al archivo de configuración de usuarios en sistemas operativos tipo Unix/Linux. Al enviar este payload como valor del parámetro "filename" en la solicitud HTTP, se elude la validación que bloquea las secuencias de navegación relativas (../) y se accede directamente al archivo sensible.

Recomendaciones de mitigación

Para mitigar la vulnerabilidad de Path Traversal, se recomienda implementar una validación estricta de las entradas proporcionadas por el usuario. Esto incluye:

  • Sanitizar y validar los parámetros de entrada para asegurarse de que no contengan secuencias de navegación no deseadas.
  • Utilizar rutas absolutas en lugar de rutas relativas para acceder a archivos y directorios.
  • Implementar controles de acceso adecuados para restringir el acceso a archivos sensibles.
  • Evitar exponer información del sistema operativo o estructura de directorios en los mensajes de error.
  • Realizar pruebas de seguridad regulares para identificar y corregir posibles vulnerabilidades.
